# 架构说明

## 分层

| 层 | 职责 | 是否含业务逻辑 |
|----|------|----------------|
| 协议层 `onebot.py` | WS 收事件、HTTP 调接口、自动重连、登录号校验 | 否 |
| 守护层 `guard.py` / `boot.py` | 登录状态机、熔断告警、启动协调 | 否 |
| 基础能力层 `lock/splitter/degenerate/ratelimit/notifier` | 横切关注点 | 否 |
| 业务模块层 `modules/` | 对话、记忆、扩展能力 | 是（部署方定义） |
| 人格层 `persona/` | 人格设定文本 | 是（部署方定义） |

## 设计原则

1. **协议与业务解耦**：换协议端只改 `onebot.py` 配置；换模型只改 LLM 调用；核心不动。
2. **人格是外部资产**：框架不预设人格，不读取部署方私有内容，不做任何泄露。
3. **失败可见优先于失败静默**：关键失败（登录、退化输出）必须告警，不静默吞掉。
4. **可测性**：核心逻辑纯函数化，时钟/存储/通知均可注入，单测不依赖真实环境。

## 数据流

```
事件 -> [频控检查] -> [合并窗] -> 业务模块 -> LLM 调用
         -> [流式切句] -> [退化检测] -> 协议层发送 -> QQ
```

任一环节的失败都有明确处理路径，不产生静默死循环。

## 为什么不用某个现成框架

见 [CAPABILITIES.md](CAPABILITIES.md) 的对比与取舍说明。简述：现成框架要么重（带桌面运行时）、要么协议传染（AGPL）、要么锁定平台。本项目的定位是"只解决工程稳定性、其余交给你"的最小脚手架。
